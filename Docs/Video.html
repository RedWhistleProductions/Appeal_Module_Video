Video Module

Appeal documentation ? Build and examples

Prefix commands below with Video. All listed arguments are required. Enabled accepts True/False, true/false, 1/0, or On/Off. Return values are available as Appeal expressions. Load an appropriate plugin before using the module.

Backends and media output

Test is an echoing diagnostic and copyable backend template; it does not decode or display real media. Appeal_FFmpeg_Video uses the FFmpeg shared libraries to demux/decode, convert to RGBA, and resample sound to stereo signed 16-bit PCM at 48 kHz. Graphics uploads frames into its normal named texture registry; Audio converts and mixes PCM on its own device and applies music volume/mute. Texture and audio integration use borrowed POD buffers; these bridge exports are native APIs, not script commands.

Call Video Update on the same thread as Graphics. Close clips before closing Graphics, or rely on normal reverse-order module cleanup. Audio may be disabled for silent/headless use. A compatible Graphics window is required for display; Audio must be loaded for sound. File I/O/decoding are synchronous and bounded per update; slow network reads can block up to their timeout. Multiple named clips may play together, with no promise of hardware acceleration.

Current limits

File playback and generated MP4, AVI, and WebM media are tested. Direct media URLs are passed to FFmpeg, not treated as web pages. Browser media-source APIs, DRM, website extraction, adaptive-stream UI, captions, HDR tone mapping, and display-rotation metadata are not implemented. Seeking requires a seekable input. Video uses a monotonic playback clock with a small decode/audio lookahead; this is basic synchronized playback, not audio-device-clock-locked production streaming.
